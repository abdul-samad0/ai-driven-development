# Migration Safety

Rules for safe, forward-compatible Django migrations. Covers data migrations, naming, and atomic behaviour.

---

## Defaults

- Always run `makemigrations` for schema migrations — never write them by hand.
- Create data migrations with `python manage.py makemigrations --empty app_name`.
- Always use `apps.get_model()` inside `RunPython` — never import models at the top level.
- Prefer `queryset.update()` over per-row `save()`. When using `save()`, always pass `update_fields`.
- Always provide a reverse: implement one if feasible, otherwise use `RunPython.noop`.

---

## Rules

### 1. Naming Convention

| Type | Pattern | Example |
|------|---------|---------|
| Auto-generated schema | `NNNN_modelname_fieldname.py` | `0002_user_is_premium.py` |
| Auto-generated (timestamp) | `NNNN_auto_YYYYMMDD_HHMM.py` | `0004_auto_20260204_0627.py` |
| Manual data migration | `NNNN_verb_noun.py` | `0081_fill_default_translations.py` |

### 2. Data Migrations (RunPython)

```python
from django.db import migrations
from django.db.models import OuterRef, Subquery

def backfill_field(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    RelatedModel = apps.get_model("myapp", "RelatedModel")

    related_qs = RelatedModel.objects.filter(parent_id=OuterRef("parent_id"))
    MyModel.objects.exclude(parent_id__isnull=True).update(
        field=Subquery(related_qs.values("field")[:1]),
    )

class Migration(migrations.Migration):
    dependencies = [("myapp", "0010_previous_migration")]
    operations = [
        migrations.RunPython(backfill_field, migrations.RunPython.noop),
    ]
```

### 3. F() Expressions for Field-to-Field Copies

```python
def sync_fields(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    MyModel.objects.exclude(
        target_field=models.F("source_field")
    ).update(target_field=models.F("source_field"))
```

---

### 4. Backfill Migrations

```python
DEFAULT_VALUE = "some default"

def fill_defaults(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    MyModel.objects.filter(field="").update(field=DEFAULT_VALUE)
```

---

### 5. Reversible Migrations

Implement a real reverse when feasible:

```python
def forward(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    for obj in MyModel.objects.all():
        # transform ...
        obj.save(update_fields=["field"])

def reverse(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    for obj in MyModel.objects.all():
        # undo transform ...
        obj.save(update_fields=["field"])

operations = [migrations.RunPython(forward, reverse)]
```

When a reverse isn't practical: `migrations.RunPython(forward, migrations.RunPython.noop)`

---

### 6. Linking Records (FK Backfill)

```python
def link_records(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    RelatedModel = apps.get_model("myapp", "RelatedModel")

    for obj in MyModel.objects.select_related("parent").filter(related__isnull=True):
        related, _ = RelatedModel.objects.get_or_create(parent=obj.parent, key=obj.key)
        obj.related = related
        obj.save(update_fields=["related"])
```

---

### 7. Separate Schema and Data Migrations

Keep schema and data migrations in **separate files** unless the data operation directly depends on the schema change in the same file.

---

### 8. Non-Atomic Migrations for Large Tables

Default Django wraps migrations in a transaction. For large tables, this causes long locks. Set `atomic = False` and batch instead:

```python
class Migration(migrations.Migration):
    atomic = False
    dependencies = [("myapp", "0010_previous_migration")]
    operations = [migrations.RunPython(backfill_in_batches, migrations.RunPython.noop)]
```

```python
def backfill_in_batches(apps, schema_editor):
    MyModel = apps.get_model("myapp", "MyModel")
    BATCH_SIZE = 1000
    ids = list(MyModel.objects.filter(field__isnull=True).values_list("id", flat=True))
    for i in range(0, len(ids), BATCH_SIZE):
        MyModel.objects.filter(id__in=ids[i:i + BATCH_SIZE]).update(field="default")
```

- Only use `atomic = False` when lock contention is a real concern
- Batch size: 500–5000 depending on row size and DB load

## Pitfalls

- **Don't import models directly** in migration files — use `apps.get_model("app_label", "ModelName")`.
- **Don't combine unrelated schema and data changes** in the same file.
- **Don't use `.all().delete()`** without considering cascading deletes.
- **Don't use per-row `save()` without `update_fields`** — slow and risks overwriting concurrent changes.
- **Don't skip the reverse** — at minimum provide `RunPython.noop`.
- **Don't assume the database is empty** — always handle existing data gracefully.
- **Don't hand-edit auto-generated operations** unless you fully understand the consequences.
- **Don't run large unbatched updates in an atomic migration** — holds a table lock for the full duration.
